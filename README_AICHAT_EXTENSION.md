# AIチャット拡張機能（LLMベース）

このドキュメントでは、藍のAIチャットモジュールに追加されたLLMベースの拡張機能について説明します。

## 概要

AIチャットモジュールは、Gemini APIを活用してより柔軟で高度な会話管理を実現します：

1. **LLMベース統合分析** - 会話の感情、意図、トピックをLLMが総合的に分析
2. **スマートメモリシステム** - LLMが重要度を判断し、関連性の高い記憶を自動管理
3. **動的パーソナライゼーション** - ユーザーとの対話履歴からLLMが好みを学習

## 機能詳細

### 1. LLMベース統合分析 (LLMAnalyzer)

Gemini APIを使用して会話を多角的に分析します。

#### 分析項目：
- **感情分析**: ポジティブ/ネガティブ/ニュートラルと詳細な感情（喜び、悲しみ、怒り、恐れ、驚き、愛）
- **トピック抽出**: メイントピック、サブトピック、キーワード、エンティティ認識
- **意図分類**: 質問、陳述、リクエスト、挨拶、別れなど
- **記憶判定**: 保存すべきか、重要度、カテゴリ、要約
- **パーソナライゼーション提案**: 好みのスタイルと推奨される調整
- **応答ガイダンス**: トーン、長さ、絵文字使用、重点ポイント

#### 特徴：
- 日本語のニュアンスを正確に理解
- 文脈を考慮した総合的な分析
- JSON形式での構造化された出力

### 2. スマートメモリシステム (SmartMemoryManager)

LLMを活用した高度な記憶管理システムです。

#### 主な機能：
- **自動記憶保存**: LLMが重要と判断した情報のみを保存
- **関連記憶検索**: LLMが文脈に基づいて最も関連性の高い記憶を取得
- **記憶の要約**: 古い記憶を自動的に要約して効率的に管理
- **動的カテゴリ分類**: LLMが内容に応じて適切なカテゴリを判定

#### 記憶の構造：
```typescript
{
  id: string;
  userId: string;
  content: string;        // 元のメッセージ
  summary: string;        // LLMによる要約
  category: string;       // LLMが判定したカテゴリ
  importance: number;     // LLMが判定した重要度（0-1）
  tags: string[];         // 関連キーワード
  relatedMemoryIds: string[]; // 関連する他の記憶
  metadata: {
    sentiment: string;    // 感情
    entities: Array<...>; // 抽出されたエンティティ
  }
}
```

### 3. ユーザープロファイル管理

対話履歴からユーザーの好みを学習し、応答をパーソナライズします。

#### プロファイル項目：
- **コミュニケーションスタイル**: フォーマル/カジュアル/バランス型
- **応答の長さ**: 簡潔/標準/詳細
- **絵文字の使用**: 多め/適度/控えめ
- **技術レベル**: 初心者/中級/上級
- **ユーモアの好み**: 高/中/低
- **興味のあるトピック**: LLMが抽出したトピックリスト
- **避けるべきトピック**: ユーザーが避けたいトピック

#### 学習プロセス：
1. 対話履歴をLLMに送信
2. ユーザーの反応（メッセージ、リアクション）を分析
3. 好みのパターンを抽出
4. プロファイルを更新

## 設定方法

`config.toml`で以下の設定が可能です：

```toml
[gemini.chat]
enableMemory = true           # 長期記憶機能の有効/無効
enablePersonalization = true  # パーソナライゼーション機能の有効/無効
```

## 使用例

### LLMによる会話分析の例：
```
ユーザー: 最近仕事が忙しくて疲れちゃった。でも来週は休みが取れそう！

LLM分析結果:
- 感情: negative → positive (疲れ → 期待)
- トピック: 仕事、休暇
- 意図: 状況報告
- 記憶すべき内容: "ユーザーは仕事で忙しく、来週休みを取る予定"
- 応答ガイダンス: 共感的、励まし、休暇の話題を展開
```

### スマート記憶検索の例：
```
ユーザー: プログラミングの新しいプロジェクトを始めようと思う

LLMが関連記憶を検索:
1. "ユーザーはTypeScriptが得意" (関連度: 0.9)
2. "以前Reactのプロジェクトを完成させた" (関連度: 0.7)
3. "週末にコーディングするのが好き" (関連度: 0.6)
```

## パフォーマンスと最適化

### API呼び出しの最適化：
- 分析は必要な時のみ実行（メモリ機能が有効な場合）
- プロファイル更新は20%の確率で実行
- 記憶の最適化は10%の確率で実行

### 記憶の管理：
- ユーザーごとに最大500件の記憶を保持
- 30日以上前の記憶は自動的に要約
- LLMが削除を提案した記憶は自動削除

### エラーハンドリング：
- API呼び出しが失敗した場合は、基本的な応答にフォールバック
- 分析結果が取得できない場合は、記憶の保存をスキップ
